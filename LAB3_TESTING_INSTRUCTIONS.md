## How to run (Android Studio on Windows)

1. **Extract the ZIP** and open the folder `MADT_Lab3_WordCounter` using **Android Studio > Open**.
2. Let **Gradle Sync** finish. Do not manually edit application source files. Keep Android Gradle Plugin 8.9.2 as defined in this project.
3. Start your existing **Pixel 6 API 35** emulator (Device Manager).
4. Open **View > Tool Windows > Gradle**, press **Execute Gradle Task** (or use Find Action to find "Execute Gradle Task"). Run the tasks below **one at a time**, exactly as written:

   - `:app:testDebugUnitTest` — executes local unit tests.
   - `:app:createDebugUnitTestCoverageReport` — generates the unit test coverage HTML report.
   - `:app:verifyLogicCoverage` — requires **100% class and method** coverage of the two pure-Java logic/model classes.
   - `:app:createDebugAndroidTestCoverageReport` — **runs** the Android UI tests on the connected emulator and generates instrumentation coverage HTML.
   - `:app:verifyAppCoverage` — cross-type coverage check combining local `.exec` and device `.ec` data for all handwritten Java application classes, including MainActivity and its nested class. Requires **100% class and method coverage** across the combined runs; run after the above steps.

   Android Studio can also run `WordCounterUiTest` from the gutter of the test class, but use the Gradle coverage task above to produce coverage evidence.

5. Check **Build Output**. Both suites should finish successfully with **zero failures**. If a test or coverage gate fails, **do not claim a pass**. Share the error (or attach the generated HTML/XML report) in the AI session that owns that test suite.
6. Save screenshots of the Gradle tests passing, the UI tests running on Pixel 6, and the HTML coverage result.

## UI scenarios

1. Valid text: all four displayed metrics are correct.
2. Empty/whitespace input: no calculation or history item.
3. Generate sample > Calculate > history appears.
4. Clear input: previous history is retained.
5. Tap history: original text is restored.
6. Activity recreation: history and metrics survive.
7. **Regression:** `9:30` counts as **one** word/number (14 words, 4 numeric tokens for full sample).
8. Multiple sample generations: next sample is selected.
9. Long text: history preview is shortened and tapping restores the full string.
10. Activity recreation: sample generation index is preserved.
11. **Regression:** top system-bar safe inset is accounted for in ScrollView padding.

## Coverage interpretation

- `verifyLogicCoverage` checks 100% **class and method coverage** of `TextMetrics` and `TextMetricsCalculator` (pure JVM classes).
- `verifyAppCoverage` checks 100% **class and method coverage** of all handwritten application Java classes by combining JVM and instrumentation coverage. This more demanding task is the relevant final gate for a strict interpretation of the Lab #3 requirement. A task declaration is **not** a measured result; report 100% only when the task actually succeeds.
- "100% class and method" does **not** mean 100% line or branch coverage. If the teacher expects line or branch coverage too, obtain the measured report and extend tests accordingly.
